Partie A
Comprendre l'ensemble

L'architecture, les dossiers, la coquille, les profils et les composants d'interface.

1 Vue d'ensemble

Rôle. Les deux principes de l'application : couches séparées, un seul document.

Application web sans serveur, sans build, sans dépendance : du HTML, du CSS et du JavaScript classique, qu'on ouvre dans Chrome ou Edge. Le casque parle en Bluetooth Low Energy ; le navigateur y accède par l'API Web Bluetooth.

Casque Muse 2capteurs + radio BLE
→
lib/muse.jsconnexion, décodage, événements
→
lib/signal, artefacts, contact, calibration
→
ui/composants d'affichage
→
projets/pages qui assemblent le tout

Deux principes structurent tout le code :

  • Séparation en couches. lib/ ne touche jamais au DOM (testable sans navigateur graphique) ; ui/ ne contient que de l'affichage ; projets/ assemble.
  • Un seul document. L'application entière vit dans index.html. Changer de page ne recharge rien : c'est ce qui garde la connexion Bluetooth ouverte (une connexion Web Bluetooth meurt avec la page qui l'a créée).

3 La coquille : routes et cycle de vie d'un projet

Rôle. Routes #/…, chargement et démontage des projets, objets partagés (muse, recorder). Fichiers : index.html, app/shell.js, app/catalogue.js.

Routage

HashEffet
#/Accueil : cartes générées depuis CATALOGUE.
#/p/<id>Projet interactif : script chargé à la demande, puis monté dans #view.
#/p/<id>/<x>Idem avec un paramètre transmis au projet (params), ex. #/p/etude/3 ouvre l'échantillon n° 3.
#/d/<id>Page de documentation, dans un iframe plein cadre.
#/dev/<id>Page de la section Développement ou rapport critique (CATALOGUE.dev, CATALOGUE.rapports), montée comme un projet. Voir Développement.

route() (dans shell.js) s'exécute à chaque hashchange : elle démonte d'abord le projet courant, puis monte le suivant. Un « jeton de navigation » évite qu'un chargement de script lent ne monte un projet que l'utilisateur a déjà quitté.

Contrat d'un projet

Projets.register({
  id: 'live',
  template: '<h1>…</h1> …',                 // HTML injecté dans <main>
  mount(root, { muse, recorder, params }) {
    // s'abonner : const off = muse.on('eeg', …);  créer timers, animations
    return () => { /* tout désabonner, tout arrêter */ };
  },
});

muse est l'instance unique de Muse, créée par la coquille au démarrage. Un projet ne crée jamais la sienne. recorder est l'instance unique de SignalRecorder (mémoire des 30 s), créée juste après : elle enregistre en permanence, quelle que soit la page. Le démontage doit tout nettoyer (muse.on retourne la fonction de désabonnement), sinon les abonnements s'accumulent à chaque visite.

  • Stockage : servie par serveur.py, l'application garde les profils en dur dans profils/profils.json (objet { clé: valeur JSON en texte }), via GET / PUT /api/profils (le PUT valide un objet de chaînes, sinon 400 ; écriture atomique tmp + os.replace ; même contrôle d'origine que les échantillons). Profiles.init({ prefix, disk = prefix==='muse2' }) lit le fichier de façon synchrone (XHR) au démarrage dans une copie mémoire _mem ; les écritures sont différées de 150 ms (fetch PUT, keepalive, vidage sur pagehide). Sans serveur (file://, autre hébergement) : repli sur localStorage. Au premier lancement avec le disque vide, les clés muse2.* du localStorage sont recopiées dans le fichier (sans vider le navigateur). init({ disk: false }) force localStorage (les tests, préfixe muse2test). Les profils ne dépendent donc plus du port ni de l'origine et survivent à l'effacement des données du site. Clés : muse2.profiles = { active, next, list } ; chaque réglage dans muse2.p.<id>.<clé>. Premier lancement : création de « Profil 1 » et reprise des réglages d'avant les profils (muse2.calibration, muse2.pipeline, muse2.mental.baseline, muse2.live.enhance). profils/ contient des données personnelles : ne pas versionner ni partager. Non testé de bout en bout dans un vrai navigateur ni sur le casque (API vérifiée par curl + tools/check.py).
  • Échantillons : recorder.saveRecording pose rec.profile (id) et rec.subject (étiquette) ; listSamples() ne renvoie que ceux du profil actif ({ all: true } : tous) ; les échantillons d'avant les profils appartiennent au premier profil. Les numéros restent uniques tous profils confondus. Fichiers : sujet BIDS sub-<étiquette>, ajouté à participants.tsv du dossier sans rien effacer ; code patient de l'en-tête EDF = l'étiquette. La mémoire des 30 dernières secondes reste commune (c'est celle du casque).
  • Changer de profil : Profiles.onChange → la coquille relance la route courante : le projet affiché est remonté et relit les réglages du nouveau profil.
  • Supprimer un profil (menu) : réglages effacés ; échantillons du navigateur supprimés ou rattachés au profil restant (recorder.reassignSamples), au choix ; fichiers du dossier jamais touchés.
  • Tests : Profiles.init({ prefix: 'muse2test' }) dans tests/index.html : les tests n'utilisent jamais les vrais réglages.

Séquence de démarrage (_open) : s'abonner à toutes les caractéristiques, puis envoyer les commandes h (pause), p50 (preset), s (start), d (resume).

Fiabilité : reconnexion et chien de garde

  • Reconnexion automatique (_retryLoop) : après une coupure involontaire, nouvelles tentatives avec des délais de 0,5 – 1 – 2 – 4 – 8 s (le dernier se répète sans fin), sans rouvrir le sélecteur d'appareil. État 'reconnecting' avec le numéro d'essai.
  • Chien de garde (_startWatchdog, 1 fois par seconde) : calcule stats.rate ; si aucun paquet EEG depuis STALL_MS = 4 s alors que le lien se dit connecté, il force la déconnexion pour relancer la boucle.
  • disconnect() volontaire met _wantConnected à faux : plus de reconnexion.

Paquets EEG perdus : numéro de séquence

Les 2 premiers octets de chaque paquet EEG sont un compteur 16 bits, propre à chaque canal (lu aussi par muse-js, réf. 7). muse._onEegPacket(canal, dataView) le compare au précédent (modulo 65 536) ; les séquences sont oubliées à chaque (re)connexion (_resetSequences(), appelé par _open).

  • Trou de 1 à Muse.MAX_FILL_PACKETS = 22 paquets (~1 s) : 'gap' (filled: true), puis 12 × n échantillons répétant la dernière valeur reçue sont émis en 'eeg' avant le paquet. Les 4 canaux restent alignés (un canal qui perd un paquet ne prend plus de retard sur les autres). Pas de NaN : les filtres récursifs en aval ne le supportent pas.
  • Trou plus grand, ou séquence qui recule : rien n'est comblé ; 'gap' avec filled: false, stats.resyncs++, le numéro reçu devient la nouvelle origine, puis 'resync' (voir ci-dessous).
  • Doublon : ignoré. stats.lost cumule les paquets perdus.

Resynchronisation ('resync'). Après un trou non comblé, les canaux ne sont plus alignés : chacun a son propre numéro. Le départ commun est le premier numéro qu'aucun canal n'a émis (le plus avancé + 1) ; les autres canaux ne sont en avance que de moins de Muse.RESYNC_WINDOW = 256 paquets. Chaque canal écarte ses paquets antérieurs à ce départ : les 4 canaux repartent au même instant. L'événement { canal, perdus, depart } sert aux briques qui apparient les canaux par rang : ArtifactDetector.resync() (garde les compteurs), GazeMeter.resync(), CalibrationContext.resync(), et le reset() de SignalPipeline. Les projets Capteurs en direct, Amélioration du signal, État mental, Calibration, Jeu des artefacts, Regard et Annotation s'y abonnent et remettent pipeline et détecteur à zéro. La barre d'état affiche dans l'infobulle de la liaison les paquets perdus et les resynchronisations.

Limites : le palier de comblement reste visible dans le signal (aucun module n'écarte ces secondes) ; logique testée sans Bluetooth sur paquets fabriqués (tests/muse.test.js), jamais observée sur le casque réel (fréquence réelle des pertes, comportement du compteur après une reconnexion, effet réel de la resynchronisation).

9 Artefacts : lib/artifacts.js

Rôle. Détection en direct et hors temps réel des clignements, sourcils, mâchoire, bâillements, regards. Utilisé par : Capteurs en direct, État mental, Étude, aperçu des échantillons.

Détecte en temps réel clignements, sourcils, mâchoire, bâillements et regards latéraux. Alimenté par detector.feed(canal, échantillons). Création : ArtifactDetector.forProfile(rate) applique d'un coup la calibration, la sensibilité (artifactSensitivity) et le secteur (50 / 60 Hz) du profil actif (Calibration, État mental en mode Casque) ; new ArtifactDetector() garde les réglages par défaut (démonstrations).

Chaîne de traitement

  1. Par canal (feed) : une moyenne lente (passe-haut 0,1 Hz) retire la dérive ; un passe-bas 10 Hz donne la partie lente (blink) ; un passe-bas 15 Hz sert à isoler le contenu rapide ; un coupe-bande secteur (Biquad, mainsHz et son harmonique, Q = mainsQ) retire le 50 / 60 Hz de ce contenu, dont l'enveloppe (valeur absolue lissée, τ = 60 ms) mesure l'activité musculaire (env).
  2. Alignement (_flush) : chaque canal arrive par paquets séparés ; les valeurs sont mises en file et traitées dès que les 4 canaux ont de la donnée.
  3. Mesures (_step), en µV :
    featuresCalcul
    blink|moyenne(AF7, AF8) de la partie lente|
    frontalHFmoyenne des enveloppes AF7 et AF8
    temporalHFmoyenne des enveloppes TP9 et TP10

  4. Niveaux : levels = mesure ÷ seuil. 1 = seuil atteint. Les seuils viennent de la calibration, sinon de valeurs par défaut (thresholds).
  5. Machines à états :
    • _updateBlink : début quand la mesure dépasse le seuil ; fin quand elle repasse sous 50 % du seuil ; émis si durée entre 60 et 900 ms ; période réfractaire de 200 ms. Ignoré pendant un épisode de mâchoire. Forme : abandonné si le front est « engagé » (voir « Forme des événements ») ou si les sourcils sont actifs ; réarmé seulement quand le signal repasse sous 50 % du seuil (sinon la déflexion qui s'éteint donne des clignements en série).
    • _updateMuscle('frown' | 'jaw') : début après 60 ms au-dessus du seuil, fin après 150 ms sous 60 % du seuil. Dominance : un des deux ne démarre que si son niveau est ≥ à celui de l'autre (le front et les tempes se contaminent mutuellement). Le front n'est plus bloqué par un clignement en cours s'il y a indice du front ; la mâchoire est supprimée pendant un clignement (sauf niveau ≥ jawBlinkMinLevel) et pendant des sourcils (voir « Forme des événements »).
    • _updateGaze : début quand |écart| dépasse le seuil pendant 150 ms (hors clignement et hors activité musculaire) ; direction = signe de l'écart (inversée si la calibration l'a décidé) ; fin quand l'écart repasse sous 50 % du seuil pendant 100 ms ; recalage de la référence si le regard dure plus de 8 s. Retour au centre : l'œil qui revient (et, hypothèse non mesurée, le passe-haut du casque) donne une contre-déviation de signe opposé, d'amplitude égale à l'aller. Le détecteur mémorise le pic (g.peak) et la fin (g.last) du dernier regard ; une déviation de signe opposé dans les gazeReturnMs (1200 ms) suivant cette fin et d'amplitude < gazeReturnRatio (1,5) × ce pic n'est pas comptée (avant : 800 ms et 0,7, ce qui ne filtrait pas un retour aussi grand que l'aller). Conséquence connue : un regard volontaire de l'autre côté dans ces 1,2 s n'est compté que s'il dure au-delà. Seuils par direction : thresholds.gazeLeft / gazeRight, repli sur thresholds.gaze. Ligne de base figée pendant un clignement, des sourcils, la mâchoire et tant que l'écart dépasse 3 × le seuil (au plus 10 s). Pas de regard si l'écart dépasse gazeMaxFactor (8) × le seuil, ni dans les gazeAfterFrontMs (2 s) qui suivent des sourcils.
    • Pouls et froncements : feedPpg(canal, échantillons) (canal 1 infrarouge, 64 Hz) calcule features.ppg = enveloppe (τ 0,25 s) de l'écart à une ligne de base lente (τ 1,5 s), divisée par une référence « calme » (τ 8 s, ne suit pas un mouvement ; recalage très lent τ 60 s ; 2 s d'apprentissage) : ≈ 1 au repos, grand pendant un mouvement du front. levels.ppg = features.ppg ÷ (thresholds.ppg × sensibilité) ; 0 sans pouls reçu depuis 1 s (le seuil est thresholds.ppg, sinon ppgFrown). Fusion : si levels.ppg ≥ 1 ET le niveau EEG des sourcils ≥ ArtifactDetector.PPG_ASSIST (0,5, toujours exigé), le froncement est compté (deux indices faibles qui concordent). Le pouls seul ne déclenche jamais rien. Seuil de pouls : thresholds.ppg calibré, sinon ppgFrown (4,5) ; avant, le pouls était ignoré sans seuil calibré.
    • Bâillement : à la fin d'un épisode de mâchoire, si sa durée dépasse yawnMinMs (1,8 s par défaut, calibrable) et que le front ou les yeux ont été engagés (niveau ≥ 0,8 pendant l'épisode), il est classé yawn plutôt que jaw.

Forme des événements

Le détecteur ne juge plus seulement un dépassement de seuil mais la forme de l'événement (mesures et limites : science, section 18). Entrée : signal brut (projets/01-live/live.js, projets/09-annotation/annotation.js) ; l'amélioration numérique (SignalPipeline) ne sert qu'à l'affichage, à l'état mental et à l'export, et la calibration est faite sur le brut.

  • Indice « front engagé » (_evidence) = pouls au-dessus du seuil OU déflexion de clignement durant plus de blinkFrownMs avec l'énergie rapide du front encore ≥ seuil des sourcils (les sourcils font une déflexion lente de 1,5 à 2,8 s, un clignement 0,06 à 0,44 s).
  • Clignement : abandonné si front engagé ou sourcils actifs ; réarmement sous 50 % du seuil ; durée max 900 ms inchangée.
  • Sourcils : débloqués pendant un clignement en cours s'il y a indice du front.
  • Mâchoire : supprimée pendant un clignement sauf si son niveau ≥ jawBlinkMinLevel (1,55 ; marge étroite : clignement appuyé 1,0 à 1,45, vraie mâchoire 1,68 à 2,4), et pendant des sourcils ou un indice du front.

Limites : valeurs choisies a priori (0,6 ; 0,25 s ; 1 s ; 80 % ; 3 impulsions ; 1,2 s ; 3 s d'intervalle), non réglées sur des essais du nouveau protocole ; protocole jamais lancé sur casque réel ; avec 7 concordances de signe sur 10 seulement dans la séance de 16:46, l'étape pourrait échouer en « sens incohérent » ; geste demandé non validé par l'utilisateur.

Résultat : cal = { version, date, floors, thresholds ({ blink, frown, jaw, gaze, gazeLeft?, gazeRight?, ppg? }), gazeSign, yawnMinMs, jawDurMs, failed }, appliqué au détecteur (applyCalibration) et enregistré dans le profil actif (clé calibration). Une étape échouée garde l'ancienne valeur. runOffline(enregistrements, only) rejoue l'analyse sans temps réel (tests).

Refaire seulement les étapes échouées

  • cal.failed liste les étapes échouées ; il est mémorisé avec la calibration, donc les « étapes à refaire » survivent à un rechargement (_initialStatuses). calibrator.failedIds en donne la liste courante.
  • start(only) ne lance que les étapes de only ; startFailed() = start(failedIds). Le plan (_plan) ajoute d'office l'étape Repos si elle n'a jamais été mesurée (plus de dépendance entre regards : une seule étape gaze).
  • Étapes à la carte : start(ids) accepte n'importe quel sous-ensemble ; les étapes non choisies gardent leurs seuils. L'interface (CalibrationPanel) propose une case par étape.
  • Les seuils des étapes non refaites sont conservés (_newDraft repart de la calibration mémorisée, y compris jawDurMs qui sert au bâillement).
  • L'état émis à onProgress contient position et total (« étape 2/3 » de cette session) en plus de stepIndex (rang dans toutes les étapes).
  • reset() oublie tout (mémoire du navigateur comprise) ; le panneau l'utilise pour « Réinitialiser ».
  • Dans CalibrationPanel, le bouton « Refaire les étapes échouées (n) » n'apparaît que s'il y a des échecs.

12 Modèle du regard : lib/gaze-model.js, lib/gaze-calibration.js

Rôle. Comparer ce que la théorie attend (l'œil est un dipôle : l'écart AF7 − AF8 est proportionnel à l'angle du regard) à ce que le casque mesure, et en tirer des chiffres lisibles. Sans interface. Utilisé par : projet Regard, scène ui/gaze-stage.js, registre des calibrations. Rien n'est testé sur casque réel. Explication physique : Les yeux.

  • Convention (celle de ArtifactDetector et du simulateur) : position du regard +1 = bord gauche de l'écran, −1 = bord droit ; un regard à gauche donne AF7 − AF8 positif quand le montage est « normal ».
  • Protocole de test (GazeModel.DURATION = 38 s, le même pour la calibration et l'étude en direct) : 2 s au centre, 8 fixations de 3 s aux positions 0,5 · 1 · 0,5 · 0 · −0,5 · −1 · −0,5 · 0, puis un balayage lent sinusoïdal de 12 s. GazeModel.target(t) → position −1..+1 (null hors protocole) ; holds() → [{ from, to, pos }].
  • Théorie : THEORY_UV_PER_DEG = 2,5 µV/°, valeur d'illustration de la page Science, pas une mesure du Muse. halfAngle(largeurCm, distanceCm) = demi-angle de l'écran (°) quand le point est au bord (94 % de la largeur) ; theoryGain(demiAngle) = µV attendus pour une position de ±1 ; expected(pos, { gain, offset }). Exemple : 15° → 37,5 µV.
  • Mesure : new GazeMeter(rate = 256) ; feed(canal, échantillons) (AF7 = 1, AF8 = 2, les autres sont ignorés) ; frames = [{ t, d }], d = AF7 − AF8 en µV passé par un passe-bas de 6 Hz, à 64 images/s ; onFrame, reset().
  • Analyse GazeModel.analyse(frames, { halfAngleDeg }) (t = 0 au début du protocole) → n, r (corrélation signée avec la position, au meilleur décalage), lagS (0 à 0,6 s : réaction + retard du filtrage), gain (µV par unité de position), rmse, noise (écart-type au centre), gainLeft / gainRight et asymmetry (|gG − gD| / moyenne), droop (rapport fin / début des fixations excentrées : 1 = pas d'affaissement, 0 = signal retombé), theoryGain, ratio (|gain| / théorie) ; null si trop peu de données.
    Ajustement (_fit) : d ≈ gain_gauche·max(pos,0) + gain_droit·min(pos,0) + dérive polynomiale de degré 3 sur les 38 s, par moindres carrés (_lsq, élimination de Gauss). Deuxième passe sans les images à plus de 3 écarts absolus médians (1,4826·MAD, minimum 1 µV) : clignements et pics (rejected = nombre d'images écartées). r = ± √(R² partiel), c'est-à-dire la part de la variance, dérive retirée, expliquée par la position. Décalage de 0 à 0,6 s par pas de 0,05 s, retenu au R² maximal. gain = moyenne des deux côtés ; gainLeft / gainRight = les deux pentes. Champs ajoutés : drift(t) (fonction), driftPtp (amplitude crête à crête de la dérive, µV), rejected, offset = niveau du centre en fin de test. Affaissement, asymétrie et bruit sont calculés sans la dérive. Limite : la dérive cubique peut absorber une partie d'un vrai signal lent (balayage), donc r est un peu sous-estimé ; le suivi libre n'a pas de retrait de dérive en continu. Premier essai sur casque réel (avant ce correctif) : r = −0,06, gain 2 µV, bruit au centre 26,7 µV, asymétrie 114 %, affaissement −11 %, tête 5,9 °/s rms ; la théorie ne s'est pas vérifiée et l'ancienne analyse ne retirait aucune dérive (AF7 − AF8 dérive de plusieurs dizaines de µV). Cause réelle non confirmée (dérive, clignements, yeux qui ne suivent pas, contact, retard…) ; le correctif n'a pas encore été revalidé sur casque.
  • Verdict GazeModel.verdict(analyse) → { level: 'bon' | 'moyen' | 'faible', text }. Seuils choisis a priori, non validés : r < 0,5 = faible ; r ≥ 0,8 et ratio entre 0,5 et 2 = bon ; sinon moyen. MIN_R = seuil de réussite de la calibration.
  • GazeCalibrator (extends StepCalibrator, inscrit au registre : id regard, order 15) : une étape de 38 s avec step.target(t) (point suivi par GazeTarget). Chaque seconde, la dernière seconde de signal brut (ctx.rawWindow) alimente un GazeMeter ; à la fin, GazeModel.analyse. Réussite si |r| ≥ MIN_R, sinon le résultat précédent est conservé. Résultat (clé gazeMap) : { version, date, gain, offset, r, lagS, noise, asymmetry, droop, ratio, halfAngleDeg, theoryGain }. API : load / save / clear, setup() / saveSetup({ widthCm, distanceCm }) (clé gazeSetup), halfAngle().
  • Scène (ui/gaze-stage.js, GazeStage) : plein écran, un point suit le protocole et un graphique en bas compare en direct le point demandé (gris), la théorie (orange), la calibration (bleu) et le réel (vert), niveau du centre soustrait. new GazeStage({ onCancel }) (bouton Annuler, touche Échap) ; run({ duration, target, frames, view, onTick, onEnd }) avec view = { gain, lagS, theoryGain, sign } ; stop(), destroy() ; GazeStage.draw(canvas, { frames, view, target, t0, t1, baseline, dark }) = le même graphique hors scène (résultats). Aucun calcul métier dans la scène.
  • Enregistrement d'une expérience : GazeModel.experimentFiles({ … }) → [{ name, data }] pour SampleFolder.writeExperiment. signal.csv : t_s, af7_uv, af8_uv, diff_uv, position_demandee à 256 Hz (brut). meta.json : protocole, théorie, écran, mesures (sans la fonction drift), calibration, contexte (clignements, tête, contact, profil) et modalités saisies. Résultats commentés : Résultats : théorie vs réalité.
  • Tests : tests/gaze.test.js (21 tests, dont « dérive et pics retirés » et l'écriture d'une expérience).

13 Qualité de contact : lib/contact.js

Rôle. Note de contact par électrode. Utilisé par : bouton « Capteurs », Guide, Capteurs en direct, État mental.

Pour chaque canal : valeur efficace (rms) du signal sans dérive lente (passe-haut 0,5 Hz) par fenêtres d'1 s ; médiane des 5 dernières. levels[i] = { rms, score, label, horseshoe, isGood }.

Alignement sur Muse. Le vocabulaire de sortie reprend celui du SDK Muse (réf. 29) : horseshoe = 1 (bon), 2 (moyen), 4 (mauvais, suspect ou absent) ; isGood = indicateur strict, vrai seulement pour « bon » ; « absent » = aucun contact. HeadMap reprend aussi la convention visuelle du « fer à cheval » de l'appli Muse : pastille pleine = bon/moyen, contour seul = mauvais, contour pointillé vide = pas de contact. L'algorithme interne de Muse n'est pas public : seuls le vocabulaire et la logique générale (peu de variance sur l'EEG brut, hors clignements) sont alignés ; les seuils chiffrés ci-dessous restent des estimations de ce projet.

  • rms < ContactQuality.ABSENT_RMS = 0,5 µV → absent ; plus de 5 % d'échantillons saturés (±990 µV) → mauvais.
  • rms < ContactQuality.SUSPECT_RMS = 3 µV → suspect (score 0, horseshoe 4, isGood faux, électrode non utilisable) : signal présent mais trop faible pour un EEG porté (10 à 50 µV rms d'habitude) ; évoque un pont électrique avec la référence (gel, sueur, électrodes qui se touchent) ou un canal bloqué. Avant, ce cas recevait la note « bon ». Affiché en rouge par HeadMap et SensorCheck, avec un conseil dans le Guide. Pas de vocabulaire Muse équivalent ; seuil non vérifié sur le casque réel.
  • sinon score = 1 − (rms − 25) / 95, borné à [0, 1] : ≥ 0,66 bon, ≥ 0,33 moyen, sinon mauvais.

13b Orientation de la tête : lib/head-pose.js

Rôle. Estimer l'orientation du casque (pitch, roll, yaw) à partir de l'accéléromètre et du gyroscope, sans DOM. Utilisé par : Capteurs en direct (avec Head3D).

API : new HeadPose({ tau = 1 }) ; accel({x,y,z}) (en g) ; gyro({x,y,z}, tMs) (en °/s, fait avancer l'estimation) ; angles → { pitch, roll, yaw } en degrés relatifs à la référence ; recenter() (la position actuelle devient la référence) ; reset() ; statique HeadPose.tilt(a) → { pitch, roll } depuis la seule gravité. Chargé après contact.js (index.html et tests/index.html). Échelles du casque (lib/muse.js) : accéléromètre 0,0000610352 g/LSB, gyroscope 0,0074768 °/s/LSB, ~52 Hz.

  • Filtre complémentaire : le gyroscope fait avancer les angles ; pitch et roll sont recalés sur la gravité avec la constante de temps tau (1 s), seulement quand la norme de l'accélération reste entre 0,8 et 1,2 g (secousse ignorée). pitch = atan2(−ax, √(ay²+az²)), roll = atan2(ay, az).
  • Yaw : gyroscope seul (pas de boussole), donc dérive lente ; « Recentrer » le remet à 0.
  • Biais du gyroscope : suivi lent (constante ≈ 5 s) tant que la vitesse reste sous 3 °/s autour du biais.
  • Rotation Rz(yaw)·Ry(pitch)·Rx(roll), intégration par angles d'Euler simples (blocage de cardan possible près de ±90° de pitch). Principe : science, orientation de la tête.
  • Tests : tests/head-pose.test.js (9 tests : inclinaison par la gravité, immobile = 0, accéléromètre seul, intégration du lacet, correction du pitch par la gravité après un mouvement rapide, absorption du biais, recentrage, secousse ignorée).

Limites (non vérifié). Le repère des axes du capteur est supposé (x vers le nez, y vers l'oreille gauche, z vers le haut, gravité ≈ +1 g sur z casque droit) et non vérifié sur le casque réel : si la tête penche du mauvais côté, il faudra inverser un axe. Aucune source en ligne vérifiée pour les axes du Muse 2. Le rendu n'a pas été testé avec un casque connecté (tests synthétiques et captures sans casque seulement).

14 États mentaux : lib/mental-state.js

Rôle. Indices de détente, concentration, somnolence, par électrode, en direct ou sur un enregistrement. Utilisé par : État mental, Étude.

Par électrode. Chaque électrode a sa propre référence (médiane de ses indices) ; le score d'un indice est la moyenne, sur les électrodes disponibles, de ln(indice / référence de l'électrode) : écarter une électrode ne biaise rien. MentalState.timeline applique la même chaîne à un enregistrement entier (fenêtres de 4 s toutes les secondes), avec une référence fournie, prise sur une portion (baselineRange) ou, à défaut, la médiane de l'enregistrement.

  • Mesure (MentalState.measure(fenêtres, { rate, raw, events, t0 })) : par électrode, Welch sur 4 s (7 segments de 1 s, recouvrement 50 %, via Signal.periodograms) en ne gardant que les segments qu'aucun artefact de sa zone ne touche ; électrode écartée (null) s'il reste moins de MIN_SEGMENTS = 3 segments. Bandes BANDS : θ 4–8, α 8–13, β 13–20 Hz (au-dessus, les muscles du front et des tempes dominent).
  • Artefacts : une seule règle (excludedFor(events, a, b)) : tout événement qui touche l'intervalle [a, b], marge comprise, écarte les électrodes de sa zone. ZONES : clignement, sourcils, regards → AF7/AF8 ; mâchoire → TP9/TP10 ; bâillement → les 4. MARGIN_S : 0,3 s pour clignement, bâillement et regards, 0 pour les muscles. Les regards latéraux écartent désormais le front (potentiel lent de dizaines de µV, énergie en delta/theta). excluded({ blink, frown, jaw, gaze, yawn }) = même table, à partir de drapeaux. En direct, MentalState.EventLog (add(e), recent(active, windowS, now), excluded(…)) tient le journal des événements du détecteur ; un épisode ouvert compte jusqu'à sa fin.
  • Indices (MentalState.indices) : détente α/(θ+α+β), engagement β/(α+θ), somnolence θ/(α+β).
  • Témoin musculaire : puissance 30–45 Hz (EMG_HZ) mesurée sur le brut (le passe-bas réglable l'atténuerait), médiane des segments propres. Au-delà de EMG_RATIO = 2 × sa valeur de référence, l'électrode est « tendue » et ne compte plus pour l'indice focus ; si toutes le sont, focusSuspended : « Concentré » ne peut pas être choisi.
  • Scores : ln(indice / référence), lissés exponentiellement (SMOOTH_S = 5 s). update() renvoie aussi deviations (écarts θ/α/β lissés, pour l'affichage seulement), muscle, focusSuspended, muscleGuard, threshold.
  • Seuil personnel (MentalState.thresholds(réf), ms.threshold) : THRESHOLD_K = 2 × écart-type du score lissé au repos, borné à [THRESHOLD_MIN = 0,1 ; THRESHOLD_MAX = 0,5]. Écart-type = 1,4826 × MAD des scores seconde par seconde de la référence × smoothingFactor() ≈ 0,56 = √(a/(2−a)·[1 + 2 Σ ρ(h)(1−a)h]), a = 1 − e−1/5, ρ(h) = 1 − h/4 (autocorrélation due aux fenêtres de 4 s avancées de 1 s ; 0,562 calculé contre 0,571 simulé). Repli sur THRESHOLD = 0,18 (≈ +20 %) pour une référence version 2, moins de SPREAD_MIN_N = 20 mesures, ou une médiane d'enregistrement. Décision : parmi les scores au-dessus de leur seuil, le plus fort rapporté à son seuil, sinon « neutre » ; un changement doit tenir HOLD_S = 3 s.
  • Référence (VERSION = 3, baselineFrom(mesures, { spread })) : { version, betaHz, relax[], focus[], drowsy[], bands: { theta, alpha, beta }, emg[], spread, seconds, date } (valeurs par électrode), sur 30 s de signal propre, mémorisée dans le profil (clé mentalBaseline) ; à défaut, les 30 premières secondes propres servent de référence automatique. Les références version 2 restent utilisables (legacy) : comparées au bêta 13–30 Hz (BETA_WIDE, betaWide), sans témoin musculaire, sans écarts θ/α/β, au seuil fixe 0,18 — à refaire pour en profiter.
  • Filtres : MentalState.statePipeline(pipe) → { pipeline, removed }, copie de la chaîne sans les pistes PIPELINE_OFF = ['eog'] : la réduction des clignements effaçait une grande partie du theta frontal, et ses poids dérivent après la référence. Utilisé en direct, par CalibrationContext et par l'Étude.

Limites connues : le seuil ne dépend pas du nombre d'électrodes ou de segments gardés ; le témoin ne voit pas une tension musculaire déjà présente pendant la référence ; rien de tout cela n'a encore été vérifié sur le casque réel. Mesure sur simulateur (300 s) — part du temps où AF7 et AF8 sont utilisés : à 20 clignements/min, 0 % avant le rejet par segment, 65 % après (43 % en comptant les faux « regards » dus à la dérive simulée) ; à 15/min, 3 % → 93 %.

Échantillons nommés

Un échantillon est une copie figée de la mémoire à un instant donné, conservée jusqu'à ce qu'on la supprime (la mémoire, elle, continue de glisser).

  • createSample() copie les anneaux (_arrays()) et les range dans le magasin IndexedDB samples (clé = numéro n) avec { n, name, createdAt, seconds, version, streams }.
  • Nom : SignalRecorder.sampleName(n, date) = échantillon-<n>-AAAA-MM-JJ_HHhMM (heure locale), par ex. échantillon-1-2026-10-07_20h04.

  • Flux de données : casque ou SignalSimulator → ArtifactDetector.forProfile → événements gaze-left / gaze-right / blink → game.input(…) ; en parallèle detector.onFrame (≈ 32 Hz) → DynamicCalibration.observe(features, game.needed()?.action, nowMs) ; le clavier de secours (← → espace) appelle les mêmes input.
  • Modes : « Jeu simple » = seuils de la calibration du profil, sans les changer ; « Calibration dynamique » = ci-dessous, sans vies (mode infini : le but est la calibration, pas le score). Le joueur arrête quand il veut (bouton « Arrêter ») ; le bilan avant/après s'affiche et les seuils sont mémorisés dans le profil actif (dyn.save()) sauf en démonstration. Quitter la page en pleine calibration applique et mémorise aussi ce qui a été appris (dyn.apply() puis dyn.save()). Le « Jeu simple » garde ses vies par niveau.
  • Démonstration : le simulateur joue les gestes attendus (d'après needed()), de façon simplifiée. Profiles.sandbox(true) : rien n'est mémorisé. Pas de nouvelle clé Profiles.KEYS (réutilise calibration).

Calibration dynamique (lib/dynamic-calibration.js, DynamicCalibration(detector) ; API : observe(features, actionAttendue, nowMs), guard(nowMs), apply() → bool, stats(), save()). Hypothèse : le joueur fait le bon geste au bon moment.

  • Mesures : clignement = features.blink ; regard = features.gaze × gazeSign (inversé pour la droite).
  • Essai = tous les instants consécutifs où le même geste est attendu, plus 0,4 s de suivi (la détection tombe avant le pic du geste) ; on garde le pic. Repos = pics par tranche de 2 s, hors essai et hors garde de 1,5 s après un geste ou un événement (guard).
  • Seuil visé = R + 0,4 × (G − R) (règle des 40 % de lib/calibration.js), G = médiane des essais retenus (un essai est retenu si son pic ≥ 1,2 × R), R = 60e centile du repos (REST_Q ; ex-80e : en jeu le joueur regarde l'écran et ses mouvements d'yeux gonflaient R). Il faut ≥ 3 essais retenus et G ≥ 1,4 × R (ex-1,5), sinon rien ne change.
  • Sens du regard inversé : si gazeSign n'était pas calibré (ou l'était à tort), un regard « demandé à gauche » se lit négatif. Chaque essai de regard vote pour un signe : _track retient la première impulsion franche de l'essai (t.first, premier instant où |v| ≥ seuil de regard) et _closeTrial vote avec son signe (this.votes) ; si ≥ 70 % des essais de regard (≥ 3, pic ≥ 1,2 × repos) se lisent du côté opposé, le gazeSign est inversé et le regard repart de zéro (stats().flips compte les inversions ; le bilan affiche « Le sens gauche / droite du regard était inversé : il a été corrigé »). Avant : le vote prenait le maximum et le minimum sur toute la durée de l'essai plus la queue ; or le retour des yeux (impulsion de signe opposé, plus grande que l'aller dans 24 essais sur 24, E6) l'emportait. Cause probable, non prouvée (déduite du code et des données, le jeu n'a pas été rejoué), de l'inversion de gazeSign à chaque série d'essais observée dans le profil p3.
  • Diagnostic à l'écran : la jauge de regard affiche « regard ◀ x · y ▶ (1 = seuil) », orientée selon gazeSign, pour voir en direct de quel côté le regard est lu et à quel niveau.
  • Mise à jour : le seuil avance de 50 % de l'écart (ex-35 %) à chaque apply() (toutes les 5 s en jeu, ex-8 s et à la fin), jamais de plus de ×0,6 / ×1,6 d'un coup. Seuils sourcils et mâchoire inchangés. apply() applique le même facteur aux seuils par direction gazeLeft / gazeRight qu'au seuil commun gaze.
  • Sans calibration préalable : seuils clignement + regard créés ; les autres étapes (rest, frown, jaw, yawn) restent dans failed, donc « à refaire » dans le projet Calibration.
  • Registre : pas d'entrée propre dans Calibrations ; elle améliore la calibration « artefacts » déjà inscrite (même clé de profil calibration), voir le registre.

Tests (tests/jeu.test.js, dans tests/index.html) : moteur (joueur parfait sans perte de vie en 2 min aux 3 niveaux, murs et barrières, toujours un couloir libre, fin de partie sans action, mode infini sans fin de partie) ; calibration dynamique sur trames synthétiques (seuil trop haut qui descend, bornes, essais sans geste écartés, signe gazeSign, sans calibration préalable, sens gauche / droite inversé détecté et corrigé puis seuil qui s'affine).

Retour utilisateur non résolu : sur casque réel, « aucun regard gauche/droite ne passe, même après longtemps ». Cause non confirmée (aucune mesure sur le casque) ; les trois correctifs ci-dessus (sens inversé, repos gonflé, diagnostic à l'écran) traitent des hypothèses et restent non validés sur casque réel. Limite : le signal de regard (écart AF7 − AF8) est une ligne de base lente, le retour au centre produit une déviation opposée, et un regard très bref (< 150 ms au-dessus du seuil, gazeMinMs) n'est jamais détecté quel que soit le seuil.

Limites : les fenêtres et durées des niveaux sont des valeurs choisies a priori, non validées sur des joueurs. L'hypothèse « le bon geste est fait » est fausse en cas de ratés : les essais sous 1,2 × repos sont écartés, mais un clignement ou mouvement involontaire au repos relève R (seuil plus haut, plus prudent). Les essais réussis sont biaisés vers le haut (seuls les gestes détectés comptent) ; le suivi de 0,4 s atténue ce biais sans le supprimer. Gestes très lents ou très faibles non traités. Le jeu ne distingue pas un regard volontaire d'un involontaire ; un clignement involontaire peut faire sauter.

30 Pièges et limites

Rôle. Ce qui a déjà posé problème.

  • Geste utilisateur : muse.connect() n'ouvre le sélecteur que depuis un clic.
  • Une connexion = un document : ne jamais naviguer vers un autre fichier HTML (rechargement) ; utiliser les routes #/….
  • RSSI indisponible : Web Bluetooth ne donne pas la puissance du signal d'un appareil connecté ; l'indice Bluetooth se base sur le débit de paquets reçus.
  • Seuils d'artefacts : heuristiques ; seule la calibration les rend fiables pour une personne et une pose de casque données.
  • Stockage du navigateur indisponible (navigation privée) : les profils et leurs réglages ne sont alors pas mémorisés d'une session à l'autre.
  • Réglages par personne : toujours passer par Profiles.get / set, jamais par localStorage directement (sinon le réglage serait commun à tous les profils, et les tests pourraient l'écraser).
  • Paquets EEG perdus : comblés par répétition de la dernière valeur jusqu'à ~1 s (Muse) ; le palier reste dans le signal et rien ne l'écarte encore des calculs.
  • État mental : jamais calculé avec la piste eog (MentalState.statePipeline) ; une référence d'avant la version 3 reste lue, mais sans témoin musculaire ni seuil personnel : la refaire. Après le coupe-bande secteur du détecteur, refaire aussi la calibration des artefacts.
  • Seuils non vérifiés sur le casque : contact « suspect » (3 µV), comblement des trous, témoin musculaire (× 2), seuil personnel (k = 2) : tous réglés sur simulateur.
  • Navigateurs : Chrome, Edge (et dérivés Chromium). Pas Firefox ni Safari.
